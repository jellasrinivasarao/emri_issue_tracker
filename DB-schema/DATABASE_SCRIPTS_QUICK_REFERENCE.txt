-- ============================================================================
-- IMPORTANT: MULTI-VENDOR WORKFLOW TABLES
-- ============================================================================

CRITICAL TABLE: map_issue_vendor_assignment
  └─ Location: master_tables_structure.sql
  └─ Purpose: Links vendors to issues for multi-vendor support
  
FIELDS:
  - issue_id           - Issue being assigned
  - vendor_id          - Vendor being assigned
  - vendor_status_id   - Vendor-specific status (from mst_issue_status)
  - is_active          - 1=active vendor, 0=rejected vendor
  - status_remarks     - Vendor-specific notes
  - status_updated_by  - User who last updated vendor status
  - status_updated_at  - When vendor status was last updated

SUPPORTING TABLE: txn_issue_status_history
  └─ Location: transaction_tables_structure.sql
  └─ Fields:
    - vendor_id        - NULL for main ticket, populated for vendor-specific changes
    - new_status_id    - Status that was changed to
    - comment          - Change notes/remarks

WORKFLOW:
  1. Issue created → vendors assigned via map_issue_vendor_assignment
  2. Each vendor gets initial status (usually "New")
  3. Vendor updates their status → txn_issue_status_history records change
  4. When ALL vendors are Resolved → main ticket auto-resolves
  5. If vendor Rejects → is_active = 0, not counted in completion


-- ============================================================================
-- FIELD NAMING CONVENTIONS
-- ============================================================================

PRIMARY KEYS:
  mst_* tables         → {table_name}_id (e.g., state_id, vendor_id)
  txn_* tables         → {table_name}_id (e.g., issue_id, history_id)
  map_* tables         → {mapping_name}_id (e.g., vendor_state_id)

FOREIGN KEYS:
  Format               → fk_{mapping_table}_{referenced_table}
  Example              → fk_map_issue_vendor_vendor
  
INDEXES:
  Primary Key          → PRIMARY KEY
  Unique Constraints   → uq_{field_names} (e.g., uq_vendor_code_org)
  Regular Indexes      → idx_{field_name} (e.g., idx_is_active)

COMMON FIELDS:
  is_active            → 1=active, 0=inactive (soft delete)
  created_at           → Timestamp when record created
  updated_at           → Timestamp when record last modified

-- ============================================================================
-- COMMON OPERATION WORKFLOWS
-- ============================================================================

WORKFLOW 1: Create New Project
  1. Insert into mst_project
  2. Insert into map_project_state (link to states)
  3. Insert into map_project_application (link to applications)
  4. Insert into map_project_service (link to services)
  5. Insert into mst_sla_configuration (define SLA)

WORKFLOW 2: Assign Vendors to Project
  1. Ensure vendors exist in mst_vendor
  2. Link vendors to states via map_vendor_state
  3. Optionally link to specific projects/applications

WORKFLOW 3: Create New Issue
  1. Insert into txn_issue (with state_id, project_id, etc.)
  2. Insert into map_issue_vendor_assignment (for each vendor)
  3. Insert into txn_issue_status_history (initial status)

WORKFLOW 4: Update Vendor Status
  1. Update map_issue_vendor_assignment.vendor_status_id
  2. Update map_issue_vendor_assignment.status_updated_at
  3. Insert into txn_issue_status_history (with vendor_id)
  4. Check if ALL vendors resolved → Update main txn_issue.status_id

WORKFLOW 5: Grant Role Permission
  1. Ensure role exists in mst_role
  2. Ensure menu exists in mst_menu
  3. Insert into map_role_privilege (role_id, menu_id, privilege_id)
  4. Set is_allowed = 1 to grant permission
